# Перевозки завода — мобильный клиент (Flutter)

Приложение для рабочих-перевозчиков завода: список активных заявок на
внутризаводскую перевозку и карточка заявки. Данные читаются из HTTP-сервиса
опубликованной базы **1С:ERP** (только GET; кнопки действий будут включены,
когда на сервере появятся POST-эндпоинты).

- Экран входа: логин/пароль пользователя 1С (Basic Auth), хранятся в
  `shared_preferences`; при ответе 401 приложение возвращает на вход.
- Экран 1 «Список заявок»: pull-to-refresh + кнопка обновления, спиннер при
  загрузке, ошибка с кнопкой «Повторить», пустой список — «Нет активных заявок».
- Экран 2 «Карточка заявки»: секции «Груз», «Маршрут», «Условия» (скрыта, если
  пусто), «Требования», исполнитель и даты внизу; статус — цветной бейдж в AppBar;
  кнопки «ВЗЯТЬ В РАБОТУ» и «ВЫПОЛНЕНО» пока отключены (серые, с подписью
  «Появится после обновления сервера», тап — SnackBar «Операция пока недоступна»).

Тестовый аккаунт: `testLog` / `7zyriqoL`.

## Требования

- Flutter 3.44 (stable) и Android SDK;
- Android-устройство с Android 6.0+ (minSdk 23);
- доступ к серверу 1С с устройства (HTTP, порт 80).

## Адрес сервера

Задаётся **одной константой** `apiBaseUrl` в
[`lib/api/api_service.dart`](lib/api/api_service.dart):

```dart
static const String apiBaseUrl = 'http://localhost/ERP_Local/hs/log';
```

На телефоне `localhost` — это сам телефон, а не компьютер с 1С, поэтому:

- **Подключение по USB** (как сейчас): выполните проброс порта —
  ```bash
  adb reverse tcp:8080 tcp:80
  ```
  после этого `localhost:8080` на телефоне указывает на этот компьютер
  (порт 80 на самом телефоне adbd занять не может — привилегированный,
  поэтому в `apiBaseUrl` указан порт 8080).
- **По Wi-Fi**: замените хост на IP-адрес компьютера в сети завода,
  например `http://192.168.1.50/ERP_Local/hs/log` (порт 80 в адресе не указывается).

Сервер за Apache отвечает `301` (регистр пути + слэш) — Dart-клиент `package:http`
проходит редирект автоматически, ничего делать не нужно.

## Запуск

```bash
flutter pub get

flutter devices            # убедиться, что телефон виден
flutter run                # на подключённом устройстве (debug, debug-подпись)
```

Готовый APK (debug-подпись, ставится без магазина):

```bash
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

Проверить связь с 1С и разбор ответа без запуска приложения:

```bash
dart run tool/check_api.dart testLog 7zyriqoL
```

## Установка на Xiaomi (MIUI)

`adb install` на MIUI падает с `INSTALL_FAILED_USER_RESTRICTED`, пока не выполнено:

1. войти в аккаунт Xiaomi (Настройки, самый верх);
2. Для разработчиков → **«Установка по USB»** — включить (после входа в аккаунт);
3. (опционально) там же **«Отладка по USB (настройки безопасности)»** — разрешает
   эмуляцию нажатий (`adb shell input tap`), если нужно управлять экраном с ПК.

## Если телефон не виден в adb

1. На телефоне: Настройки → Для разработчиков → включить **«Отладка по USB»**
   (сам «режим разработчика» недостаточен).
2. Выбрать режим USB **«Передача файлов (MTP)»**, а не «Только зарядка».
3. При первом подключении принять диалог доверия к компьютеру (RSA-отпечаток).
4. Проверить: `adb devices` — устройство должно быть в состоянии `device`,
   а не `unauthorized`.

## Особенности данных 1С (уже учтено в коде)

- Ключи JSON — русские; значения — строки-представления (`Количество` приходит
  и строкой «25»), `ТребуетсяФото`/`ТребуетсяМастер` — булевы.
- `Подразделение` добавлено в API вместе с мобильным клиентом; старые ответы
  без этого поля безопасны: строка в списке не показывается, в карточке «—».
- Даты приходят как `«07.09.2026 9:55:14»` (час без ведущего нуля) или в ISO;
  пустая дата 1С (`«01.01.0001 0:00:00»` / `«0001-01-01T00:00:00»`)
  отображается как «—».
- Пустые строки (`Куда`, `ОсобыеУсловия`, `Исполнитель`) → «—» / секция скрыта.
- 404 отдаёт `{"error": "Заявка … не найдена."}` — текст показывается пользователю.

## Подключение кнопок, когда сервер обновится

POST-контракт уже описан в `lib/api/api_service.dart`:

- `POST /requests/take` `{"num": "…"}` → `ApiService.takeRequest(num)`;
- `POST /requests/complete` `{"num": "…", "photo": "<base64>"}` →
  `ApiService.completeRequest(num, photo)`.

Нужно раскомментировать вызов `_postJson(...)` в этих методах и включить
`onPressed` у кнопок на экране карточки (`request_detail_screen.dart`,
см. TODO в `_disabledAction`).
